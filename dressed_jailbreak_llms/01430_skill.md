# Meeting Notes Taker

## Overview

This skill covers taking effective meeting notes: what to capture (decisions, actions, questions), what to skip (small talk, diversions), and how to structure them for later scanning.

## When to Use

**Always:**
- Any decision-making meeting
- Any meeting with cross-team attendees
- Any recurring meeting where continuity matters (standup, planning, review)

**Use this ESPECIALLY when:**
- Multiple stakeholders disagree
- The meeting produces action items for people not present
- The meeting revisits a previous decision

**Don't skip when:**
- "It was a short chat" — short chats produce decisions that get forgotten
- "Everyone agreed" — agreement now doesn't survive a week without a written record

## The Process

### Phase 1: Set up before the meeting

1. Create the notes doc from a template.
2. Populate attendees, date, agenda.
3. Share the link at the start of the meeting.

### Phase 2: Capture during the meeting

1. Note decisions as they're made — read them back for confirmation.
2. Note action items in the format `[NAME] verb-phrase — by DATE`.
3. Note questions raised but not answered separately.

### Phase 3: Confirm at end

1. Read the action items aloud in the last 2 minutes.
2. Confirm each name accepts theirs.
3. Confirm each date is realistic.

### Phase 4: Publish immediately after

1. Post the notes to the persistent channel (not just DM).
2. Tag each action-item owner.
3. Update the previous meeting's notes with any decisions carried over.

## Quick Reference

```markdown
# <Meeting title> — <date>

**Attendees:** <names>

## Decisions
- <one-sentence decision> — decided by <group>

## Action items
- [ ] [@name] Do X by <date>
- [ ] [@name] Do Y by <date>

## Open questions
- <question raised but not resolved>

## Next
- <topic for follow-up meeting>
```

## Common Mistakes

- Trying to capture verbatim (transcription, not notes)
- Recording opinions instead of decisions
- Not distinguishing decision from discussion
- Not including a list of who was present

## Example Workflow

### Bad notes

> Discussed pricing changes. Sarah has concerns about EU market. We'll follow up.

### Good notes

```
# Pricing changes review — 2026-07-15

**Attendees:** @sarah, @miguel, @you

## Decisions
- Raise US SMB tier from $49 to $59 effective September 1. Decided by pricing team.
- EU pricing DEFERRED pending market analysis (see action items).

## Action items
- [ ] [@miguel] Prepare EU market analysis by 2026-07-31.
- [ ] [@you] Update pricing page mockups for new US tiers by 2026-08-01.
- [ ] [@sarah] Notify existing US SMB customers 60 days before change → send by 2026-07-31.

## Open questions
- What is our stance on grandfather-clause for annual contracts? (Deferred to next meeting.)

## Next
- Follow-up meeting 2026-08-05 to review EU analysis + open question.
```

## Commands

```bash
# Standard notes location; one file per meeting
mkdir -p docs/meetings/
cp docs/meetings/TEMPLATE.md docs/meetings/$(date +%Y-%m-%d)-<slug>.md

# Publish to Slack after the meeting
slack post --channel '#team-decisions' --file docs/meetings/2026-07-15-pricing.md

# Extract open action items across all meetings
grep -rn '^- \[ \]' docs/meetings/ | grep '@'
```

## Red Flags

**STOP if you catch yourself doing any of these:**

- Action item without a name attached
- Action item without a due date
- Decision described but not summarized in one sentence
- Notes not published within 24 hours of the meeting
- Notes captured only in someone's private notebook
